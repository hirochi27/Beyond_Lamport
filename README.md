# Beyond Lamport

時計のずれと不確実性を考慮し、分散環境におけるメッセージの発生順序を確率的に推定する実験用プロトタイプです。

クライアントとシーケンサ間の通信から時計オフセットを推定し、補正したタイムスタンプと不確実性を使って、メッセージ間の先行確率を計算します。その結果から有向グラフを構築し、トポロジカルソートによってメッセージを並べます。

## 背景と目的

```https://dl.acm.org/doi/10.1145/3772356.3772401```
上記論文のアルゴリズムを再現する。

クライアントごとの時計にずれがあると、ローカルのタイムスタンプをそのまま比較しても、実際の発生順序と一致するとは限りません。また、ネットワーク遅延によって、シーケンサへの到着順序も発生順序から入れ替わります。

Beyond Lamportでは、時計のずれを測定し、そのばらつきも含めて扱うことで、発生順序をどこまで推定できるかを検証します。

## 主な機能

- 4つのタイムスタンプを用いた時計オフセットとRTTの推定
- ウォームアップとRTT外れ値の除外
- クライアントごとのオフセット分布の推定
- クライアント間のオフセット差分布の計算・固定（freeze）
- メッセージの発生時刻をシーケンサ時計基準に補正
- 正規分布モデルによるメッセージ間の先行確率の計算
- 信頼度に基づく有向グラフの構築と循環の回避
- トポロジカルソートによるメッセージの並べ替え
- 人工的な時計オフセットとジッタを使った比較実験

## 処理の流れ

1. 各クライアントがシーケンサにプローブを送信する。
2. プローブから時計オフセットとRTTを計算する。
3. RTTの外れ値を除外し、オフセットの平均・標準偏差を求める。
4. 必要なサンプルが揃ったら、クライアント間のオフセット差分布を計算してfreezeする。
5. 各クライアントからタイムスタンプ付きメッセージを送信する。
6. 時計オフセットの平均を使って、メッセージの発生時刻を補正する。
7. メッセージの各ペアについて、一方が他方より先に発生した確率を計算する。
8. 信頼度の高い辺から、循環を作らないように採用する。
9. 得られたグラフをトポロジカルソートする。

## 時計オフセットの推定

1回のプローブで、次の時刻を記録します。

| 記号 | 内容 |
| --- | --- |
| `t1` | クライアントの送信時刻 |
| `t2` | シーケンサの受信時刻 |
| `t3` | シーケンサの送信時刻 |
| `t4` | クライアントの受信時刻 |

時計オフセットとRTTは、次の式で求めます。

```text
offset = ((t2 - t1) + (t3 - t4)) / 2
RTT    = (t4 - t1) - (t3 - t2)
```

オフセットは「シーケンサ時計 − クライアント時計」の向きです。クライアントのタイムスタンプに平均オフセットを加算し、シーケンサ時計基準の推定時刻に変換します。

```text
推定発生時刻 = クライアントのタイムスタンプ + 平均オフセット
```

現在の実装では、RTTの絶対値がRTT中央値の絶対値の2倍を超えるサンプルを除外します。不確実性は、採用したオフセットの標準偏差に `sigma_multiplier` を掛けて求めます。

## セットアップ

Python 3.10以上を使用してください。

以下はLinux / WSLでの実行例です。

```bash
git clone https://github.com/hirochi27/Beyond_Lamport.git
cd Beyond_Lamport

python3 -m venv .venv
source .venv/bin/activate

python -m pip install fastapi "pydantic>=2" "uvicorn[standard]"
```

現時点では `requirements.txt` が空のため、依存パッケージを直接インストールします。

## 実行方法

### 1. シーケンサを起動する

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

起動後、以下にアクセスできます。

- ヘルスチェック: http://127.0.0.1:8000/api/health
- APIドキュメント: http://127.0.0.1:8000/docs

### 2. 比較実験を実行する

別のターミナルで、リポジトリのルートに移動し、仮想環境を有効化して実行します。

```bash
source .venv/bin/activate

python app/experiment_runner.py \
  --clients 5 \
  --samples 100 \
  --warmup 5 \
  --interval 0.1 \
  --messages-per-client 10
```

この例では、5クライアントがそれぞれ5回のウォームアップと100回の計測を行い、その後、それぞれ10件のメッセージを送信します。

時計オフセットの推定から、先行確率の計算、トポロジカルソートまでをまとめて実行します。

### 主な実験オプション

| オプション | 内容 | デフォルト |
| --- | --- | --- |
| `--sequencer` | シーケンサのURL | `http://127.0.0.1:8000` |
| `--clients` | クライアント数 | 必須 |
| `--samples` | 各クライアントの計測回数 | `100` |
| `--warmup` | 分布に含めない事前通信回数 | `5` |
| `--interval` | プローブ間隔（秒） | `0.1` |
| `--messages-per-client` | 各クライアントのメッセージ数 | `1` |
| `--clock-offsets-ms` | 各クライアントの時計オフセット（ミリ秒、カンマ区切り） | `0,50,-80,130,-170` |
| `--clock-jitter-stddev-ms` | プローブに加える時計ジッタの標準偏差（ミリ秒） | `40` |
| `--sigma-multiplier` | 不確実性を求める標準偏差の倍率 | `2.0` |
| `--comparison-output` | 比較レポートの出力先 | `ordering_comparison.txt` |

`--clients` を6以上にする場合は、クライアント数以上のオフセットを `--clock-offsets-ms` に指定してください。

## 結果の確認

実行結果には、次の情報が表示されます。

- 推定した時計オフセット分布
- クライアント間のオフセット差分布
- 各メッセージの補正後の推定発生時刻
- メッセージの各ペアの先行確率
- トポロジカルソートで得られた順序
- 循環を避けるために除外した辺（存在する場合）

比較レポート `ordering_comparison.txt` には、次の3種類の順序を出力します。

1. デモ内で記録した実際の生成時刻の順序
2. 補正前のクライアントタイムスタンプの順序
3. 補正後の推定発生時刻の順序

レポートの「並び替えミス数」は、実際の生成順序に対して、補正後の順序で前後が逆転したメッセージペアの数です。トポロジカルソート結果の評価値ではありません。

## 現在の制約

- データはサーバプロセスのメモリに保存され、再起動すると消えます。
- `/api/experiment/start` は時計推定の状態を初期化しますが、保存済みメッセージは削除しません。独立した実験を繰り返す際は、サーバを再起動してください。
- オフセット推定は通信の往路・復路の対称性を仮定するため、遅延の非対称性による誤差が残ります。
- 先行確率は正規分布と独立性を仮定したモデル上の値であり、実際の発生順序や因果関係を保証するものではありません。
- 現在のグラフ構築では、各ペアで確率の高い向きを採用します。95%などの信頼度による足切りは行っていません。
- freezeしたオフセット差分布は保存・取得できますが、現在の先行確率計算は各メッセージの補正時刻と不確実性を使用します。
- デモでは、プローブに時計ジッタを加えます。メッセージのタイムスタンプには固定の平均オフセットを使用します。
- メッセージの全ペアを比較するため、件数が増えると計算量と保存量も増加します。

現段階では、時計推定と確率的な順序付けの挙動を検証するための実験実装です。
